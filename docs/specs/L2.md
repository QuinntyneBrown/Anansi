# Anansi Platform - L2: Detailed Requirements & Acceptance Criteria

> Anansi is an all-in-one platform for photographers, with future
> customization for Toronto Black photographers. This document expands every L1 requirement
> into detailed, testable acceptance criteria.
> Each requirement has a unique ID for traceability. Format: `AREA-SECTION.NUMBER`

---

## 1. Client Galleries

---

### 1.1 Photo & Video Upload

#### GAL-1.1.1 Browser Drag-and-Drop Upload
- **Given** a photographer is on the collection upload page
- **When** they drag one or more image files (JPEG, PNG, GIF) onto the upload area
- **Then** the files are uploaded with a progress indicator per file, and appear in the collection upon completion
- Upload area must accept click-to-browse as an alternative to drag-and-drop
- Multiple files can be uploaded simultaneously with parallel upload streams
- Failed uploads must show an error message and allow retry without re-selecting successful files

#### GAL-1.1.2 Bulk Folder Upload
- **Given** a photographer drags a folder containing images onto the upload area
- **When** the upload completes
- **Then** a new collection is created with the folder name, and sub-folders become sets within the collection
- Nested folder structures must be preserved as nested sets
- Empty folders must be ignored

#### GAL-1.1.3 Lightroom Classic Plugin
- **Given** a photographer has installed the Anansi Lightroom plugin
- **When** they publish a collection from Lightroom Classic
- **Then** the images are uploaded to the corresponding Anansi collection
- Re-publishing edited images must update the existing image (not create a duplicate)
- Collection structure in Lightroom must sync to collection/set structure in Anansi
- Client favorite lists must be visible within the Lightroom plugin

#### GAL-1.1.4 RAW File Support
- **Given** a photographer on a Pro or Ultimate plan
- **When** they upload RAW files (CR2, CR3, NEF, ARW, DNG, RAF, ORF, RW2)
- **Then** the system processes and displays preview thumbnails, and the originals are available for download
- RAW files must not be available for print fulfillment (JPEG only for prints)

#### GAL-1.1.5 Video Upload
- **Given** a photographer uploads a video file (MP4, MOV, AVI, M4V)
- **When** the upload completes
- **Then** the video is processed for streaming playback up to 4K resolution (plan-dependent)
- Video upload limits by plan: Basic=30min HD, Plus=1hr HD, Pro=2hr 4K, Ultimate=5hr 4K
- Custom video thumbnails must be selectable from the uploaded video frames
- Video playback must support adjustable speed and Chromecast/AirPlay casting

#### GAL-1.1.6 File Validation
- The system must reject files exceeding the maximum allowed size per plan
- The system must reject unsupported file formats with a clear error message naming the format
- JPEG files must be accepted up to 50MB per file
- Video files must be accepted up to 4K resolution (3840x2160px)

### 1.2 Gallery Organization

#### GAL-1.2.1 Collections and Sets
- **Given** a photographer creates a new collection
- **When** they add photos to it
- **Then** photos can be organized into named sets (sub-groups) within the collection
- Collections must have a title, optional description, and configurable settings
- Sets within a collection must be independently titled and described
- Photos can be moved between sets via drag-and-drop
- The order of sets within a collection must be manually sortable

#### GAL-1.2.2 Bulk Gallery Creation
- **Given** a photographer selects "Bulk Create Galleries"
- **When** they configure settings (privacy, design, download, store) and specify multiple gallery names
- **Then** all galleries are created simultaneously with the specified settings applied
- Client info (name, email) must be attachable to each gallery during bulk creation
- Preset settings must be applicable during bulk creation

#### GAL-1.2.3 Star/Bookmark
- **Given** a photographer views their collection list
- **When** they star a collection or individual photos
- **Then** starred items appear in a dedicated "Starred" tab for quick access
- Bulk starring must be supported (select multiple, then star)
- Unstarring must remove items from the Starred tab immediately

#### GAL-1.2.4 Collection Presets
- **Given** a photographer configures gallery settings (privacy, design, download, store, language)
- **When** they save these settings as a named preset
- **Then** the preset can be applied to any new or existing collection with one click
- Presets must store: cover style, theme (light/dark), fonts, colors, layout, download settings, store settings, privacy settings, language
- Multiple presets must be saveable and manageable (rename, delete, update)

### 1.3 Gallery Design & Customization

#### GAL-1.3.1 Cover Styles
- The system must offer at least 7 cover styles (e.g., Reef, West, Oakwood, Edge, and others)
- Each cover style must be previewable before applying
- Cover photo must be selectable from the collection's images
- Cover photo focal point must be adjustable

#### GAL-1.3.2 Video/GIF Covers
- **Given** a photographer edits a collection's cover settings
- **When** they provide a YouTube or Vimeo URL
- **Then** the video plays as a looping background on the gallery cover page
- GIF files must also be supported as cover backgrounds
- Video covers must autoplay on mute and loop continuously

#### GAL-1.3.3 Theme Toggle
- **Given** a photographer configures a collection
- **When** they toggle between light and dark theme
- **Then** the gallery's entire client-facing UI switches to the selected theme
- Theme selection must be per-collection (not global only)
- Both themes must maintain WCAG AA contrast ratios for text

#### GAL-1.3.4 Typography
- At least 6 curated font families must be available
- Font selection must apply to all client-facing text in the collection
- Font changes must be previewable in real-time

#### GAL-1.3.5 Color Palettes
- At least 9 color palettes must be available
- Colors must apply to backgrounds, text, buttons, and UI accents
- Custom hex color entry must be supported on paid plans

#### GAL-1.3.6 Grid Layouts
- Two layout modes must be available: Vertical grid (portrait emphasis) and Horizontal grid (landscape emphasis)
- Layout selection must be per-collection
- Both layouts must be responsive on mobile devices

#### GAL-1.3.7 Set Titles & Descriptions
- **Given** a photographer edits a set within a collection
- **When** they add or modify the title and description
- **Then** the title and description are displayed to clients above the set's photos
- Descriptions must support basic text formatting (bold, italic, line breaks)

#### GAL-1.3.8 Slideshow Mode
- **Given** a client views a collection
- **When** they activate slideshow mode
- **Then** images display full-screen in sequence with smooth transitions
- Slideshow speed must be adjustable (slow, medium, fast)
- Auto-loop toggle must be available
- Manual navigation (next/previous) must work during slideshow

### 1.4 Photo Delivery & Downloads

#### GAL-1.4.1 Download Options
- Clients must be able to download individual images or the entire gallery
- Download must be available in multiple resolutions:
  - Web size: 640px, 1024px, 2048px (long edge)
  - High resolution: 3600px or original resolution (plan-dependent)
- Downloads must be delivered as ZIP files for multi-image downloads
- Original resolution downloads must be available on Pro and Ultimate plans

#### GAL-1.4.2 Download PIN
- **Given** downloads are enabled for a collection
- **When** a client attempts to download
- **Then** they must enter a 4-digit PIN before the download begins
- PIN must be auto-generated per collection but editable by the photographer
- PIN can be optionally disabled per collection
- PIN must be separate from the collection password

#### GAL-1.4.3 Download Limits
- **Given** a photographer sets a download limit on a collection
- **When** the limit is reached
- **Then** further downloads are blocked with a message indicating the limit has been reached
- Limits must be configurable as total photos per collection
- The photographer must be able to reset or modify the limit at any time

#### GAL-1.4.4 Async Download with Notification
- **Given** a client requests a download of a large gallery
- **When** the ZIP file is being prepared
- **Then** the client can leave the browser and receives an email notification when the download is ready with a download link
- Download link must expire after a reasonable period (e.g., 7 days)

#### GAL-1.4.5 Download Activity Tracking
- **Given** a photographer views a collection's activity tab
- **Then** they can see: who downloaded (name/email), when (timestamp), and what (individual photos or full gallery)
- Activity must be filterable by date range and action type
- CSV export of download activity must be available

### 1.5 Proofing & Favorites

#### GAL-1.5.1 Favorite Lists
- **Given** a client is browsing a collection
- **When** they click the favorite/heart icon on a photo
- **Then** the photo is added to their active favorite list
- Clients must be able to create multiple named favorite lists
- Photos can be added to or removed from favorite lists at any time
- Favorite count per list must be visible to the client

#### GAL-1.5.2 Comments on Favorites
- **Given** a client has favorited a photo
- **When** they add a comment or edit request to the favorited photo
- **Then** the comment is visible to the photographer in the favorites dashboard
- Comments must support free text (no character limit below 500 characters)
- Photographer must be notified when a client adds comments

#### GAL-1.5.3 Preset Favorite Lists
- **Given** a photographer creates a collection
- **When** they configure preset favorite list categories (e.g., "Album Picks", "Social Media", "Retouching")
- **Then** clients see these pre-created categories and can add photos to them
- Preset lists must be configurable before publishing the collection

#### GAL-1.5.4 Favorite Limits
- **Given** a photographer sets a favorite limit (e.g., max 50 photos)
- **When** a client reaches the limit
- **Then** they cannot add more photos and see a message indicating the limit
- The client must be able to remove photos to make room for new selections
- The limit must be configurable per collection

#### GAL-1.5.5 Favorite List Actions
- Clients must be able to:
  - Share a favorite list via unique link
  - Download all images from a favorite list (subject to download PIN and limits)
  - Send all images from a favorite list as a digital download to any email address
- Photographers must be able to export favorite lists as:
  - Lightroom-compatible copy list
  - CSV file with filenames

#### GAL-1.5.6 Favorite Activity Dashboard
- **Given** a photographer navigates to the favorites activity dashboard
- **Then** they can see all active favorite lists across all collections
- Each list shows: client name, collection, number of photos, comments, date last modified
- Photographer must be notified (in-app and optionally via email) when a client completes a favorite list

### 1.6 Privacy & Access Control

#### GAL-1.6.1 Collection Password
- **Given** a photographer enables password protection on a collection
- **When** a visitor navigates to the collection URL
- **Then** they must enter the correct password before any content is visible
- Password must be configurable and changeable at any time
- Incorrect password must show an error without revealing collection contents

#### GAL-1.6.2 Client Exclusive Access
- **Given** a photographer sets a separate client-exclusive password
- **When** a client enters the exclusive password
- **Then** they see additional sets that are hidden from public/general password holders
- Visibility of each set must be independently configurable for public vs. client-exclusive access

#### GAL-1.6.3 Homepage Password
- **Given** a photographer enables homepage password protection
- **When** a visitor navigates to the photographer's gallery homepage
- **Then** they must enter a password before seeing any collections listed
- This must be independent of per-collection passwords

#### GAL-1.6.4 Email Registration Gate
- **Given** a photographer enables email registration on a collection
- **When** a visitor navigates to the collection
- **Then** they must enter their name and email before viewing any content
- Collected emails must be viewable and exportable by the photographer
- This can be combined with password protection (email first, then password)

#### GAL-1.6.5 Private Photos
- **Given** a client marks a photo as private
- **Then** the photo is hidden from all other viewers (including other password holders)
- Only the original client and the photographer can see private photos
- Photographer must be able to see which photos are marked private in the activity tab

#### GAL-1.6.6 Collection Expiration
- **Given** a photographer sets an expiry date on a collection
- **When** the expiry date passes
- **Then** the collection status changes from "Published" to "Hidden" (not deleted)
- The photographer must be notified before expiration
- Expiry date must be extendable after it has passed
- Content must not be deleted, only access removed

#### GAL-1.6.7 Auto Expiry Reminder Emails
- **Given** a collection is approaching its expiry date
- **Then** automated reminder emails are sent to configured recipients
- Recipients must be configurable: specific clients, or all guests who viewed/downloaded/favorited/purchased
- Timing must be configurable (e.g., 7 days before, 3 days before, on expiry day)
- Reminder email content must be customizable

---

### 1.7 Sharing & Social

#### GAL-1.7.1 Email Invitations
- **Given** a photographer sends a gallery invitation
- **When** they compose the email using a template
- **Then** the branded email is sent with a direct link to the collection
- Email templates must support: custom subject line, body text, header image
- If the collection is password-protected, the password must optionally be includable in the email
- Delivery status must be trackable (sent, opened)

#### GAL-1.7.2 Social Media Sharing
- **Given** a client is viewing a collection or individual image
- **When** they click the share button
- **Then** they can share via: Facebook, Instagram, Pinterest, WhatsApp, Messenger, Threads, email, and copy link
- Shared content must include Open Graph metadata (title, description, preview image)
- Both full collection and individual image sharing must be supported

#### GAL-1.7.3 Quick Share
- **Given** a photographer selects specific photos within a collection
- **When** they generate a Quick Share link
- **Then** a unique URL is created that shows only the selected photos
- Quick Share links must be independent of the collection's privacy settings
- Links must be revocable by the photographer

#### GAL-1.7.4 QR Code Generation
- **Given** a photographer views a collection
- **When** they generate a QR code
- **Then** a scannable QR code is created that links to the collection
- QR code must be downloadable as an image file (PNG)

#### GAL-1.7.5 Gallery Embedding
- **Given** a photographer wants to embed a gallery on an external website
- **When** they access the embed options
- **Then** they receive embed code (iframe or JavaScript snippet) that displays the gallery on any website
- Embedded galleries must respect the collection's privacy settings

---

### 1.8 Multi-Language Support

#### GAL-1.8.1 Language Selection
- At least 8 languages must be available: English, Spanish, French, German, Dutch, Chinese (Simplified), Portuguese, Swedish
- Language can be set per collection or as a default for all new collections
- All client-facing UI text must be translated (buttons, labels, prompts, messages)
- All automated emails related to the collection must be sent in the selected language

---

### 1.9 Gallery Activity & Analytics

#### GAL-1.9.1 Activities Tab
- Each collection must have an Activities tab showing:
  - Download activity (who, when, what resolution, individual/full)
  - Favorite activity (who, which photos, which list, comments)
  - Private photo activity (which photos marked private, by whom)
  - Email registration activity (name, email, timestamp)
- All activity must include timestamps
- Activity must be filterable by type and date range

#### GAL-1.9.2 Google Analytics Integration
- **Given** a photographer connects their Google Analytics (GA4) property
- **Then** gallery visitor activity is tracked: page views, visitor count, geography, session duration
- Integration must use the GA4 Measurement Protocol or tag injection

## 2. Online Store (E-Commerce)

---

### 2.1 Product Catalog

#### STR-2.1.1 Print Products
- The store must support selling: photographic prints (multiple paper types), mounted prints, canvas prints, metal prints, wood prints, framed prints, wall art, large format prints, square prints, standouts, bamboo panels
- Each product type must have configurable sizes and variations
- Product preview must overlay the client's selected photo on the product image

#### STR-2.1.2 Photo Albums & Books
- The store must support selling custom photo albums and books
- Hundreds of customization options (cover type, paper, size, page count)
- Bulk pricing markup tool for album/book variations

#### STR-2.1.3 Greeting Cards
- Built-in card designer with hundreds of templates
- Clients can select photos and customize card layout
- Support for various card sizes and paper types

#### STR-2.1.4 Digital Downloads
- **Given** a client purchases a digital download
- **When** payment is confirmed
- **Then** the digital file is automatically delivered
- Single photo or full gallery downloads must be available
- Resolution options must be configurable by the photographer

#### STR-2.1.5 Packages
- **Given** a photographer creates a package
- **When** they bundle physical and/or digital products together at a set price
- **Then** the package appears as a single purchasable item in the store
- Package contents and pricing must be fully configurable

#### STR-2.1.6 Self-Fulfilled Products
- **Given** a photographer adds a custom self-fulfilled product
- **When** a client orders it
- **Then** the photographer is notified to handle printing and shipping
- Custom products must support: name, description, price, variations, shipping methods

---

### 2.2 Fulfillment

#### STR-2.2.1 Automatic Lab Fulfillment
- **Given** a client orders a lab-fulfilled product
- **When** payment is confirmed
- **Then** the order is automatically sent to the configured print lab for production and shipping
- Shipping must be white-label (no lab or platform branding on packages)
- Order cost is deducted from client payment; photographer receives the markup as profit
- Lab color correction options must be configurable per product

#### STR-2.2.2 Self-Fulfillment
- **Given** a client orders a self-fulfilled product
- **When** payment is confirmed
- **Then** the photographer receives a notification with order details and client shipping address
- The photographer must be able to mark the order as shipped and add tracking info

#### STR-2.2.3 Lab Partner Management
- The system must integrate with multiple print labs (minimum: WHCC, ProDPI, Miller's, Loxley Colour)
- Photographers must be able to select their preferred lab
- Lab pricing (cost) must be displayed alongside photographer markup and final client price

---

### 2.3 Pricing & Revenue

#### STR-2.3.1 Custom Pricing
- **Given** a photographer views a product's pricing settings
- **Then** they can see: cost (lab price), markup (profit), and final price (client-facing)
- Each product size/variation must be individually priceable
- Manual price entry and percentage-based markup must both be supported

#### STR-2.3.2 Bulk Markup Tool
- **Given** a photographer selects a product category
- **When** they apply a percentage markup
- **Then** all variations of that product are priced accordingly in one action
- Bulk markup must not override individually customized prices unless explicitly confirmed

#### STR-2.3.3 Price Sheets
- **Given** a photographer creates multiple price sheets
- **Then** different price sheets can be assigned to different collections
- Download-only price sheets (digital-only, no physical products) must be supported
- A default price sheet must be assignable for new collections

#### STR-2.3.4 Commission Structure
- Free plan: 15% platform commission on all store sales
- All paid plans: 0% platform commission
- Commission structure must be clearly displayed in account settings

---

### 2.4 Promotions & Gift Cards

#### STR-2.4.1 Coupon Codes
- **Given** a photographer creates a coupon
- **Then** the following coupon types must be supported:
  - Percentage off (entire order or specific items)
  - Fixed amount off (entire order or specific items)
  - Free giveaway ("Buy X, Get Y Free")
- Coupons must support: expiration date, usage limit, minimum order threshold
- Clients must apply coupon codes at checkout

#### STR-2.4.2 Coupon Banner
- **Given** a photographer enables a coupon banner
- **Then** a promotional message with coupon code displays at the top of the gallery/store
- Banner text, color, and visibility must be configurable

#### STR-2.4.3 Gift Cards
- **Given** a photographer creates a gift card
- **Then** it can be configured with: custom dollar amount, optional expiry date
- Gift cards must be deliverable via branded email or shareable as a code
- Gift card balance must apply automatically at checkout
- Remaining balance after partial use must be saved for future purchases

---

### 2.5 Store Payments

#### STR-2.5.1 Payment Methods
- The store must accept: credit/debit cards, Apple Pay, Google Pay, PayPal
- Stripe must be the primary payment processor
- Offline payment acceptance must be supported (photographer records cash/check payments)

#### STR-2.5.2 Tax Configuration
- **Given** a photographer configures tax settings
- **Then** taxes are automatically calculated and displayed during checkout
- Tax rates must be configurable by region/jurisdiction
- Tax data must be tracked and available in financial reports

#### STR-2.5.3 Shipping Configuration
- **Given** a photographer or lab has shipping settings configured
- **Then** shipping costs are calculated and displayed during checkout
- Multiple delivery methods must be configurable (standard, express, etc.)
- Free shipping promotions must be supportable via coupons

#### STR-2.5.4 Order Management
- **Given** an order is placed
- **Then** the photographer can view: order details, payment status, fulfillment status, tracking info
- Order history must be searchable and filterable
- Order notifications must be sent to the photographer in real-time

## 3. Website Builder

---

### 3.1 Templates & Core Builder

#### WEB-3.1.1 Template Library
- At least 8 professionally designed templates must be available
- Templates must be categorized: business (brand/services focus), portfolio (work/contact focus), one-page (everything on single page)
- Each template must be previewable before selection
- Template switching must preserve all content (text, images, pages, blog posts)

#### WEB-3.1.2 Flex Editor
- **Given** a photographer opens the website editor
- **Then** they can:
  - Add, remove, resize, and reposition any element via drag-and-drop
  - Use 100+ ready-made layout blocks (pre-designed sections)
  - Create custom layouts using blank blocks
  - Switch between desktop, tablet, and mobile preview modes
  - Customize each breakpoint independently
- Element types must include: images, text, video embeds, buttons, shapes, sliders, carousels, image grids, accordions
- Grid/alignment guides must be available for precise positioning
- Layer management (bring to front, send to back) must be supported

#### WEB-3.1.3 Draft Sites
- **Given** a photographer wants to experiment with designs
- **Then** they can maintain up to 10 simultaneous draft sites
- Drafts must be fully independent (different templates, content, settings)
- Any draft can be published to become the live site

---

### 3.2 Content & Elements

#### WEB-3.2.1 Page Management
- Supported page types: homepage, portfolio, about, services, contact, pricing, gallery, blog, custom
- Pages must be addable, removable, reorderable in the navigation
- Each page must have a configurable URL slug
- Password protection must be available per page or for the entire site

#### WEB-3.2.2 Client Gallery Blocks
- **Given** a photographer adds a Client Gallery block to a page
- **Then** their Anansi client galleries are displayed directly within the website
- Galleries must be browsable without leaving the website
- Multiple display options (grid, featured collection, etc.) must be available

#### WEB-3.2.3 Instagram Feed Integration
- **Given** a photographer connects their Instagram account
- **Then** a live feed of their Instagram posts displays on the website
- Configurable options: number of photos, size, click behavior (open in Instagram or lightbox)

#### WEB-3.2.4 Custom Embed Code
- **Given** a photographer adds a custom code block
- **When** they paste HTML, JavaScript, or iframe code
- **Then** the content renders on the page
- Must support: tracking pixels, third-party widgets, custom forms, video players
- Available on Pro plans

#### WEB-3.2.5 Landing Page Templates
- Ready-made landing page templates must be available for one-click addition
- Templates must cover common use cases (booking, mini session promo, etc.)

---

### 3.3 Blog

#### WEB-3.3.1 Blog Post Management
- **Given** a photographer creates a blog post
- **Then** they can add: title, body text, images, custom URL, categories
- Posts must support rich text formatting, inline images, and embedded content
- Publication date must be configurable (schedule for future publication)
- Post duplication must be supported
- Free plan: 5 blog posts; paid plans: unlimited

#### WEB-3.3.2 Blog Layouts
- At least 3 blog page layouts must be available: grid, stacked, alternated cards
- Pagination must be configurable
- "Load More" button must be available as an alternative to traditional pagination
- Category filtering must be supported

#### WEB-3.3.3 Blog Migration
- Tools must be available to migrate existing blog content from other platforms
- Migration must preserve post titles, body content, images, and publication dates

### 3.4 Typography & Design

#### WEB-3.4.1 Font System
- At least 1,000 font families must be available from the built-in library
- Custom font upload must be supported (WOFF, WOFF2, TTF, OTF formats)
- Font family, size, weight, and letter spacing must be configurable per element or site-wide
- Curated font themes must be available for quick application

#### WEB-3.4.2 Color System
- At least 40 color palettes with 200+ combinations must be available
- Colors must be applicable to: entire site, individual blocks, or selected text
- Custom hex color entry must be supported

#### WEB-3.4.3 Animations
- At least 4 site-wide animation types must be available: fade in, scale up, slide in, unfold
- Animations must trigger on scroll
- Animation toggle must be available (enable/disable site-wide)

### 3.5 SEO & Discovery

#### WEB-3.5.1 SEO Manager
- **Given** a photographer opens the SEO Manager

  - Edit page titles and meta descriptions for each page

#### WEB-3.5.2 AI Alt Text Generation
- **Given** a photographer has images without alt text

- **Then** descriptive alt text is automatically generated for each image

#### WEB-3.5.3 AI Page Descriptions

#### WEB-3.5.5 Social Sharing Images

### 3.6 Hosting & Security

#### WEB-3.6.1 Hosting
- All websites must be served with free unlimited hosting
- No bandwidth limits or throttling
- Free SSL certificate auto-created and auto-renewed for all sites

#### WEB-3.6.2 Custom Domain
- **Given** a photographer on a paid plan configures a custom domain
- **When** they update their DNS records as instructed
- **Then** their website serves on the custom domain with SSL
- Step-by-step domain connection instructions must be provided
- Both apex domains and subdomains must be supported

#### WEB-3.6.3 Password Protection
- **Given** a photographer enables password protection
- **Then** they can protect individual pages or the entire website

#### WEB-3.6.4 Right-Click Protection
- **Given** the right-click protection setting is enabled (default: on)

- The setting must be toggleable in Settings > Advanced

#### WEB-3.7.2 Google Analytics Integration

## 4. Studio Manager (CRM & Business Tools)

---

### 4.1 Contacts & CRM

#### CRM-4.1.1 Contact Types
- Three contact types must be supported: Client, Lead, Other
- Each contact must store: first name, last name, email, phone, address, notes, type
- Contact type must be manually changeable at any time

#### CRM-4.1.2 Contact Profiles
- **Given** a photographer views a contact profile
- **Then** they can see in one place: contact details, all documents (contracts, invoices, questionnaires), email history, sessions/bookings, linked galleries, payment history
- All associated items must be navigable from the contact profile

#### CRM-4.1.3 Automatic Lead Conversion

## 11. Security & Platform

---

### 11.1 Data Security

#### SEC-11.1.1 Encryption
- All data in transit must use TLS 1.2 or higher
- All payment data must be handled by Stripe (PCI DSS compliant); the platform must never store raw card numbers
- Passwords must be hashed using bcrypt or equivalent

#### SEC-11.1.2 Content Protection
- Gallery password protection must prevent any content from loading before authentication
- Download PIN must be validated server-side before file download begins
- Right-click protection must suppress the browser context menu on image elements
- Watermarks must be applied server-side as overlays (not client-side CSS that can be bypassed)

---

### 11.2 Account Management

#### SEC-11.2.1 Authentication
- Photographers must create accounts with email and password
- Password recovery via email reset link must be available
- Session management with automatic timeout for inactive sessions
- Secure logout must clear all session tokens

#### SEC-11.2.2 Account Settings
- Photographers must be able to manage: personal info, business info, notification preferences, connected integrations, billing/plan, password change
- Account deletion must be available with data export option before deletion

#### SEC-11.2.3 Storage Monitoring
- Current storage usage must be displayed in account settings
- Warnings must appear when approaching storage limits (e.g., 80%, 90%, 95%)
- Storage usage breakdown by collection must be available

#### UX-11.3.1 Gallery Assist
- **Given** a client opens a gallery for the first time

#### UX-11.3.2 Responsive Design
- All client-facing pages must be fully responsive (mobile, tablet, desktop)

#### UX-11.3.3 Content Delivery
- Photos must be served via CDN for fast global delivery
- Image thumbnails must be generated server-side for fast gallery loading

- Video streaming must use adaptive bitrate for varying connection speeds
